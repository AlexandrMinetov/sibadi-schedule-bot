## Требования к итоговому боту

- 20:00 по Омску (Asia/Omsk, UTC+6, то есть 14:00 UTC): ежедневно публиковать расписание на следующий день.
- Каждые 15 минут проверять изменения на сегодня и завтра, сообщать об изменениях и по возможности редактировать уже опубликованное расписание.
- /today, /tomorrow, /week (понедельник–воскресенье текущей недели), /help должны работать через webhook практически сразу, не ждать опроса GitHub.
- Все ответы и рассылки только в настроенной теме Telegram; игнорировать обычные сообщения, другие темы и команды другим ботам. Не хранить тексты участников/идентификаторы отправителей.
- Удобное форматирование (жирные заголовки, номер пары, время, дисциплина, преподаватель, аудитория, подгруппа при наличии); ссылка на официальный сайт.
- Закреплять только автоматически опубликованное ежедневное расписание и откреплять только ранее закрепленное самим ботом. Отсутствие прав закрепления не должно ломать рассылку. Ответы на команды не закреплять.
- Не дублировать ежедневные сообщения и уведомления; учитывать сбои, задержки, временную недоступность API, смену недели, отсутствие занятий. При некорректном/пустом ответе не объявлять отмены.
- Бесплатный тариф Cloudflare; не требовать покупки домена, VPS или платных API. Учитывать реальные лимиты и задержки бесплатного тарифа.

## Cloudflare: конфигурация

Секреты Worker: BOT_TOKEN, CHAT_ID, THREAD_ID, WEBHOOK_SECRET. Опционально BOT_USERNAME (без @, значение по умолчанию уже в коде).
KV namespace: SIBADI_STATE. Binding variable: STATE.
Cron Trigger: `*/15 * * * *` (UTC).
Worker routes:
- GET / — безвредная проверка доступности.
- POST /check — авторизованная диагностика API СибАДИ, Telegram getMe и KV, не отправляет сообщений.
- POST /activate — регистрация команд, установка Telegram webhook, включение мониторинга.
- POST /deactivate — остановка мониторинга и удаление webhook.
- POST /telegram — прием обновлений Telegram с проверкой заголовка X-Telegram-Bot-Api-Secret-Token.

Административные запросы требуют заголовка Authorization: Bearer <WEBHOOK_SECRET>. Не передавать секрет через URL.

### Безопасная ручная диагностика из Windows PowerShell

```powershell
$secret = [Net.NetworkCredential]::new("", (Read-Host "WEBHOOK_SECRET" -AsSecureString)).Password
$url = "https://sibadi-schedule-bot.vkspaz780.workers.dev"
$headers = @{ Authorization = "Bearer $secret" }
Invoke-RestMethod -Method Post -Uri "$url/check" -Headers $headers
```

Ожидается ok=True, корректный username бота, количество занятий на сегодня/завтра, active=False до активации. Только после успешной проверки и отключения старого workflow:

```powershell
Invoke-RestMethod -Method Post -Uri "$url/activate" -Headers $headers
```

Не запускать /activate с неизвестной конфигурацией. Если Codex не имеет авторизованного доступа к Cloudflare, честно сказать об этом; не имитировать действия в панели. Пользователь хочет максимально автономную помощь, но вход в аккаунт и ввод секретов выполняются им при необходимости.
